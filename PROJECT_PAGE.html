Postmark Webhooks receives bounce, spam complaint and delivery notifications from Postmark and suppresses outbound Drupal mail to addresses that bounced or complained. It does not send mail; pair it with the Postmark module or another backend using Drupal's mail manager.

Features

  • HTTP Basic Auth with a timing-safe password comparison. An unconfigured endpoint returns 503; missing or incorrect credentials return 401. The webhook secret lives in settings.php, never in exported configuration.
  • Hard-bounce suppression without a time window, soft-bounce suppression for 30 days by default, and configurable spam-complaint windows. Durable per-recipient evidence survives event-history retention.
  • Case-insensitive matching of every To, Cc and Bcc recipient, versioned retry identity, and mailbox-redacted watchdog messages.
  • Event history without provider descriptions or raw JSON payloads, with configurable cron retention defaulting to 90 days.
  • Settings form, policy preview, suppression inspector, audited recipient export/erasure, and drush postmark-webhooks:status user@example.com.
  • Optional Mailer Plus adapter and optional read-only provider reconciliation. Listed in the Chronicle package group on Drupal's Extend page.

Post-installation

Install with composer require drupal/postmark_webhooks:^1.0 and enable Postmark Webhooks. Put the secret in settings.php, not exported configuration:

$settings['postmark_webhooks.webhook_secret'] = getenv('POSTMARK_WEBHOOK_SECRET') ?: '';

In your Postmark server's message stream, configure bounce, spam complaint and delivery webhooks using https://postmark:URL_ENCODED_SECRET@example.com/api/webhooks/postmark. Replace the example host and encoded password. Postmark sends the password through HTTP Basic Auth; the admin UI never displays it.

Use HTTPS and an edge IP allowlist using Postmark's current webhook IP addresses. Preserve the Authorization header through proxies. Postmark does not provide X-Postmark-Signature or HMAC signatures; see its webhook documentation.

Visit /admin/config/services/postmark-webhook to configure suppression and retention. HardBounce, BadEmailAddress, ManuallyDeactivated and Unsubscribe bounce types suppress without a time window. Transient, SoftBounce, DnsError, MailboxFull and MessageTooLarge use the soft-bounce window (0 disables it). SpamComplaint and SpamNotification use the complaint window (0 means no time limit). Delivery, Open, Click, Subscribe and unknown events are log-only.

Sites upgrading from 1.0.0-alpha1 must run database updates, including restartable 250-row batches. Back up first. There is no supported downgrade; restore the pre-upgrade dump with the previous package files. History erasure does not restore consent or reactivate delivery.

Requirements

PHP 8.3 or later, Drupal 10.3 or 11, and a Postmark account configured to send webhooks. No mail-sending module is required merely to receive events.

Similar projects

Postmark provides outbound sending. Postmark Webhooks provides receiving and Drupal-side suppression. Mail System can select a backend that uses Drupal's mail manager.

Known limitations

  • Direct Symfony Mailer transports that do not use Drupal Mailer Plus or hook_mail_alter are not suppressed unless callers use the shared policy. Enable the optional Mailer Plus adapter when sending through Mailer Plus.
  • Event retention and recipient-history erasure do not delete durable suppression and do not restore consent. Deleting history is not a reactivation.
  • This is not an inbound email parser. Optional reconciliation is GET-only and does not change Postmark's suppression list.
  • Named source profiles in settings.php are optional. The shared webhook secret remains the default.
